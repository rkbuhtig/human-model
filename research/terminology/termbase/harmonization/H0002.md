# H0002 — 전략 설정·행동 수행·결과 사슬 조화

## 대상 후보와 concept

- `X-CH05-033` — Decision·ActionOut·actual occurrence·world outcome·receipt 공백
- `X-CH06-010~014` — pledge·strategy configuration Receipt·저장 경로
- `X-CH06-034` — Receipt가 ActionOut보다 먼저 생성됨
- `X-CH06-035` — body authorization·veto·execution state 부재
- `X-CH06-036` — Choice·StrategyAdoption·ActionOut·PerformedAction·ExternalOutcome·관측 결과 분리 요구
- `C0001` — 행동 경로 선택
- `C0002` — 외부 발생
- `C0003` — 세계 결과 상태
- `C0004` — occurrence record
- `C0007` — 실제 탐색·비교 노동
- `C0009` — 수행·지출 회계 기록

## 조화 유형

`ROLE SPLIT / MERGE / ENGINE-ONLY / HISTORICAL-ONLY / HOLD`

새 C-ID를 만드는 조화가 아니다. Chapter 05·06이 한 실행 사슬에 나열한 역할을 기존 concept와 기술 역할로 다시 배치한다.

## 조화 계기

Chapter 05는 다음 경계를 명시했지만 실제 world response와 receipt stage를 구현하지 않았다.

```text
Decision
≠ ActionOut
≠ actual occurrence
≠ world outcome
≠ outcome record
```

Chapter 06은 strategy knob에서 생성된 `Receipt`가 `ActionOut`보다 먼저 존재함을 드러냈다.

```text
strategy configured
→ Receipt minted
→ ActionOut
→ ? body authorization
→ ? performed action
→ ? external outcome
→ ? outcome observation
```

따라서 기존 `Receipt`는 실제 행동이나 결과의 영수증일 수 없다. 또한 `ActionOut`은 외부로 보낼 명령·출력일 뿐 실제 수행된 행동이 아니다.

## 판정

### 1. Decision / StrategyAdoption

`MERGE → C0001`

여러 가능한 경로 가운데 이후 수행 대상으로 하나를 채택했다는 역할은 C0001의 행동 경로 선택 경계에 포함한다.

- 선택된 전략 내용과 그 선택을 기록한 payload는 구분한다.
- `StrategyAdoption`이라는 이름이 독립 인간 모듈을 뜻하지 않는다.
- 설정값을 담은 `Receipt`는 C0001이 아니라 기술 기록 역할이다.

### 2. ActionOut / Gate_Action

`ENGINE-ONLY`

`ActionOut`은 선택된 결정을 외부 실행기로 전달하는 명령·출력 표현이다. 실제 occurrence를 보증하지 않는다.

```text
ActionOut emitted
≠ body permitted
≠ action performed
≠ world changed
```

`Gate_Action`도 이 출력 생성 경로의 구현 gate이며 현재 인간 concept로 승격하지 않는다.

### 3. PerformedAction

`MERGE → C0002`

외부 세계에서 실제로 수행된 행동은 C0002의 외부 occurrence에 포함한다.

- 행동이 실제로 성립했다는 판정만 병합한다.
- 수행에 앞선 선택·의도·명령 출력은 포함하지 않는다.
- 신체 내부의 motor execution·permission·veto 전체를 C0002로 흡수하지 않는다.

### 4. performed-action record / action receipt

`MERGE → C0004`

실제 행동 occurrence가 성립했다는 내용을 이후 참조할 수 있도록 보존한 기록은 C0004의 occurrence record에 포함한다.

- 수행을 기록한 사실과 수행 occurrence 자체는 분리한다.
- strategy configuration Receipt는 수행 기록이 아니다.
- work·spend 회계 기록은 C0009이며 action occurrence record와 자동 동일시하지 않는다.

### 5. ExternalOutcome

`MERGE → C0003`

선행 행동 occurrence 뒤 세계·관계가 이른 결과 상태는 C0003의 세계 결과 상태에 포함한다.

- 결과를 발생시킨 후속 반응 occurrence와 결과 상태를 구분한다.
- 성공·합의·해결만 결과로 인정하지 않는다.
- 결과가 관측·기록됐다는 사실은 별도다.

### 6. outcome observation / outcome receipt

`HOLD`

현재 자료는 다음을 충분히 가르지 못한다.

```text
outcome state
≠ outcome observed
≠ observation artifact
≠ outcome record
≠ claim-specific evidence
```

`outcome receipt`를 C0003·C0004·evidence 계열 중 어디에 둘지는 observation / claim-support cluster에서 판정한다.

### 7. configuration Receipt 계열

`ENGINE-ONLY`

다음은 strategy knob configuration과 그 저장·접근 계약을 나타내는 기술 역할이다.

- `Receipt`
- `PledgeFn`
- `AttachMeta`
- `Receipt-only`
- `PayloadFirewall`
- `pledge_t`, `pledge_{t-1}`, `pledge_next`

이 기록은 실제 수행·지출·외부 결과·의무 성립을 보증하지 않는다.

### 8. pledge 명칭

`HISTORICAL-ONLY`

`pledge`는 초기의 미래 자기서약과 후기의 controller strategy payload를 모두 가리켜 역할이 이동했다. 현재 concept 명칭으로 유지하지 않는다.

- 자기서약·의도·약속의 인간적 관계는 별도 근거가 필요하다.
- 현재 확인된 후기 역할은 configuration Receipt 계열의 기술 이력이다.

### 9. BodyAuthorization

`HOLD`

Chapter 06은 body permission·veto·execution state의 부재를 지적하지만 독립 concept의 긍정 정의와 대비 사례를 제공하지 않는다.

- 외부 행동 수행 전에 신체 허가가 필요한 경우가 있을 수 있다.
- 인지적 탐색·비교 노동 전체의 필수 단계로 승인하지 않는다.
- permission, veto, motor execution, pain, recovery, unmet repair demand를 하나로 합치지 않는다.

## 기존 concept에 미치는 영향

### C0001

`Decision`과 `StrategyAdoption`의 선택 역할을 연결한다. configuration Receipt와는 분리한다.

### C0002

외부로 실제 수행된 행동을 occurrence의 한 형태로 받는다. `ActionOut`과 body execution 전체는 받지 않는다.

### C0003

`ExternalOutcome`을 선행 occurrence에 귀속되는 결과 상태로 받는다. 관측·기록은 받지 않는다.

### C0004

실제 행동 occurrence에 관한 action receipt를 occurrence record로 받는다. configuration Receipt와 outcome receipt는 받지 않는다.

### C0007

실제 처리 노동과 외부 행동 occurrence의 관계를 교차 분류로 남긴다. 수리·탐색 노동의 수행 내용은 C0007, 외부 행동이 실제 성립했다는 사건 분류는 C0002다.

### C0009

work/spend accounting record 범위를 유지한다. action occurrence record를 C0009에 흡수하지 않는다.

## 이 조화가 보존하는 것

```text
선택됨
≠ 명령이 출력됨
≠ 몸이 허가함
≠ 실제 행동이 수행됨
≠ 세계 결과가 생김
≠ 결과가 관측됨
≠ 각 단계가 기록됨
```

이 경계를 잃으면 설정 Receipt나 ActionOut만으로 행동이 실제 수행됐다고 판정하거나, 행동 수행만으로 의도한 결과와 그 관측까지 자동 승인하게 된다.
