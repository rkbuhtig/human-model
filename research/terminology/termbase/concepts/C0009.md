# C0009

## 작업 설명

수행·지출·의존성·귀속에 관한 여러 기술 기록을 한 파일에서 다뤘던 원본 ID다. cardinality 감사 결과 현재 내용은 하나의 concept가 아니라 관련 기록 주제 분야와 분할 후보 inventory에 가깝다.

## 현재 판정

`HOLD / SUBJECT-FIELD SPLIT`

기존 `ENGINE-ONLY` concept 판정을 철회한다. 일부 후보가 ENGINE-ONLY일 가능성은 높지만, 하나의 본질과 정확성 조건을 공유하는 단일 concept로 확인되지 않았다.

C0009는 삭제하지 않는다. 기존 참조를 보존하면서 분할 후보와 후속 cluster를 가리키는 임시 원본 ID로 유지한다.

## 연결된 입력 후보

- `X-CH03-034` — 실행 dependency trace
- `X-CH03-035` — 수행 노동과 비용의 검증 가능한 기록
- `X-CH04-019` — influence·search provenance와 warrant 공백
- `X-CURR-016` — record·provenance·receipt가 계보를 보존함
- `X-CH05-024~027` — decision input·rotation parameter·audit record 분리
- `X-CH06-018` — Bill의 obligation·consequence·line-item 과적재
- `X-CH06-025~026` — LedgerCore 역할 혼합

## cardinality 감사

기존 정의와 특성표는 다음을 접속했다.

```text
수행됐다는 사실
수행량
금액·자원 지출
참조
의존성
귀속
```

`이 중 일부를 감사할 수 있다`는 것은 단일 concept의 본질이 아니라 subject field의 소속 조건이다.

### 분할 후보 inventory

| 후보 | 표상 대상 | 정확성 조건 | 현재 상태 |
|---|---|---|---|
| work-performance record | 어떤 노동이 수행됐는가 | 실제 수행과 일치하는가 | HOLD |
| work-quantity record | 수행량·처리량 | 단위·측정 규칙이 타당한가 | HOLD |
| expenditure record | 어떤 자원이 얼마나 소비됐는가 | C0008 실제 지출과 일치하는가 | HOLD |
| dependency trace | 어떤 실행·입력에 의존했는가 | provenance graph가 정확한가 | ENGINE 후보 / HOLD |
| attribution record | 수행·비용이 누구·무엇에 귀속되는가 | attribution rule이 타당한가 | HOLD |
| occurrence record | occurrence가 성립했는가 | C0004 경계 | C0004, 별도 |
| claim evidence | 특정 claim을 무엇이 지지하는가 | evidence·warrant 경계 | evidence cluster |

각 후보는 표상 대상과 오류 조건이 다르므로 synonym으로 병합하지 않는다.

## definition gate

- 서로 다른 대상을 잇는 `및`: 감지
- `양·참조·의존성·귀속` 복수 열거: 감지
- `중 일부를`: 감지
- 단일 genus + differentia 재작성: 실패

판정은 즉시 다중 C-ID 발급이 아니라 `HOLD / SUBJECT-FIELD SPLIT`이다.

## concept 관계 후보

- work-performance record `RELATED-TO C0007 후보군`
- expenditure record `RELATED-TO C0008`
- occurrence record `RELATED-TO C0004`, 동일하지 않음
- work/spend record: 공통 상위 record의 종개념 후보
- dependency trace / attribution record: provenance·audit record의 종 또는 audit package의 부분 후보
- configuration Receipt: `RELATED / ENGINE-ONLY`, 수행·지출을 표상하지 않음
- Bill line item: record 계열과 인접하지만 obligation·realized consequence와 분리 필요
- claim evidence: `RELATED`, evidence cluster로 이관

## 확인된 부정적 경계

```text
actual work
≠ actual expenditure
≠ occurrence record
≠ work record
≠ spend record
≠ dependency trace
≠ attribution record
≠ claim evidence
```

이 경계는 유지하지만, 그 부정적 경계만으로 C0009라는 단일 양성 concept를 승인하지 않는다.

## 인간 현상 근거

C0009 전체를 하나의 인간 내부 concept로 유지할 근거는 없다. 기술 기록 후보 각각도 구현 artifact와 사용 조건을 별도로 확인해야 한다.
