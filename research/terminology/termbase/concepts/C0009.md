# C0009

## 작업 설명

어떤 탐색·비교·수리 노동과 자원 지출이 수행됐다는 사실, 금액·참조·의존성·귀속을 보존하는 실행·회계 기록을 다룬다. 실제 노동, 실제 지출, strategy configuration, generic CommitRecord, action occurrence record, 외부 명제의 진실 근거, 인간의 책임 수용과 합치지 않는다.

## 현재 판정

`ENGINE-ONLY`

현재 확보된 본질적 차별 특성은 `WorkEvent`, Billing, receipt, trace, accounting처럼 구현·감사 구조에서만 확인된다. 인간 현상 설명에서 독립 내부 concept로 유지해야 할 코퍼스 확인 사례는 없다.

이 판정은 이 기록이 불필요하다는 뜻이 아니다. 현재 연구와 구현에서는 실제 노동·지출과 그 기록을 분리하는 기술 concept가 필요하지만, 이를 인간 내부 메커니즘으로 승격하지 않는다. Chapter 05·06의 다양한 `record`, `Receipt`, `Bill`도 같은 이름을 쓴다는 이유만으로 C0009에 흡수하지 않는다.

## 인간 현상 근거

없음.

Chapter 03·04의 사회적·체험적 사례와 Chapter 06의 Repair·Relief 장면은 실제 노동과 비용의 필요성을 설명하지만, 인간 내부에 별도 `WorkEvent`·Billing receipt가 존재한다는 근거를 제공하지 않는다. Chapter 05·06은 오히려 여러 기술 기록이 서로 다른 대상을 표상하며, configuration Receipt가 실제 수행 전에 존재할 수 있음을 보여준다. 따라서 `KEEP`을 부여하지 않는다.

## 상위 개념과 관계

- 상위 개념 후보: 수행과 지출에 관한 감사 가능 기록
- `C0007`과의 관계: C0007은 수행된 노동이고 C0009는 그 노동에 관한 기록이다.
- `C0008`과의 관계: C0008은 실제 자원 지출이고 C0009는 지출량·귀속에 관한 기록이다.
- `C0004`와의 관계: 둘 다 기록 계열이지만 대상이 다르다. performed-action record가 action occurrence의 성립만 표상하면 C0004이고, 수행 노동·비용·귀속을 별도로 회계하면 C0009와 교차할 수 있다.
- `X-CH03-034`와의 관계: execution trace는 C0009의 한 기술 하위 형태일 수 있지만 claim evidence와 동일하지 않다.
- `X-CURR-016`과의 관계: generic record·provenance·receipt는 C0009보다 넓으므로 해당 역할만 부분 연결한다.
- `X-CH05-026`과의 관계: generic CommitRecord는 decision과 분리된 기술 기록이지만 work/spend를 표상하지 않으면 C0009가 아니다.
- `X-CH06-012`와의 관계: strategy configuration Receipt는 선택된 knob를 기록할 뿐 performed action이나 expenditure를 보증하지 않는다.
- `X-CH06-018`과의 관계: Bill의 line-item 역할만 기록 계열과 인접하며 obligation과 realized consequence는 별도 후보다.
- evidence / claim support와의 관계: record integrity와 claim-specific EvidenceLink·Warrant는 별도 cluster에서 판정한다.

## 이 구분이 보존하는 것

실제로 수행하고 소비한 것과, 그 수행·소비가 있었다고 회계된 것을 구별한다. 또한 strategy를 설정한 기록, action occurrence record, decision 입력, pointer rotation, obligation line item, claim evidence를 서로 다른 기록 역할로 남긴다. 이 경계를 잃으면 configuration Receipt나 action receipt가 있다는 이유만으로 노동량과 비용이 실제로 회계됐다고 단정하거나, 실행 trace를 외부 명제의 진실 근거로 과대 승격하게 된다.

## 경계 재압축 이력

- 무너진 경계: accounting value ≠ accounting stage ≠ receipt ≠ derived readout
- 위치: Chapter 04 §8.5의 R05 `A`와 MeaningFlux 이중 배치, `X-CH04-026`
- 재압축 방식: `A`가 값 묶음, 실행 후 accounting 단계, receipt 역할을 함께 맡고 MeaningFlux가 `R`과 `A`에 중복 배치됨
- 발생한 손실: 무엇을 읽은 값인지, 이번 실행이 만든 기록인지, 다음 상태에 저장할 값인지 구분이 닫히지 않음

- 무너진 경계: decision input ≠ rotation parameter ≠ audit record
- 위치: Chapter 05의 CommitDecisionIn·CommitRecordIn과 type residue, `X-CH05-024~027`
- 재압축 방식: next refs와 audit refs가 decision input schema에 잔존하거나 같은 Commit 입력 묶음으로 표현됨
- 발생한 손실: 무엇이 결정 내용을 바꾸는지, 무엇이 다음 pointer를 교대하는지, 무엇이 단지 감사를 위해 남는지 구분하기 어려워짐

- 무너진 경계: configuration receipt ≠ performed-action receipt ≠ obligation line item ≠ realized consequence
- 위치: Chapter 06의 Receipt와 Bill, `X-CH06-012`, `X-CH06-018`, `X-CH06-034`
- 재압축 방식: 행동 전에 mint된 knob Receipt와 미래 청구·후과·line item을 하나의 receipt/billing 계열처럼 읽음
- 발생한 손실: 전략 설정, 실제 수행, 부담 성립, 후과 발생, 기록 게시를 독립적으로 판정하기 어려워짐

## 정의 초안

특정 탐색·비교·수리 노동과 자원 지출이 수행됐다는 사실 및 그 양·참조·의존성·귀속을 이후 감사할 수 있도록 보존한 기술 기록으로서, 실제 노동·지출, strategy configuration, generic CommitRecord, action occurrence record, 외부 명제의 진실·warrant와 별도로 판정되는 것.

## 명칭

- 권장 용어: 미정
- 작업용 서술: 수행·지출 회계 기록
- 역사적 명칭: `WorkEvent`, Billing, Accounting, Acct, receipt
- 현재 기술 명칭: 일부 receipt / provenance / trace 역할

인간 연구 glossary에 발행할 명칭이 아니라 현재 구현·감사 어휘의 조화 대상으로 유지한다. `Receipt`, `CommitRecord`, `Bill`, `action receipt`라는 철자 전체를 C0009의 허용 명칭으로 승인하지 않는다.

## 경계 조화

- `H0002` — performed-action record는 C0004에 연결하고 C0009를 work/spend accounting record로 유지함

## 남은 불확실성

- work record, spend receipt, dependency trace, attribution record를 하나의 상위 concept 아래 둘 범위
- C0004 occurrence record와의 공통 상위 record concept
- claim-specific EvidenceLink와 execution provenance의 정확한 경계
- 하나의 action receipt가 occurrence와 work/spend를 동시에 표상할 때의 복수 분류 규칙
