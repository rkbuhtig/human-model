# Chapter 09 Terminology Intake — Scope

## 1. 조사 목적

Chapter 09는 기억 내용이 달라져도 같은 `나`를 말하려 한 0121~0122 지층을 조사한다.

이번 intake의 목적은 정체성에 대한 단일 정의를 만드는 것이 아니다. 같은 사람을 설명한다는 이유로 다음 역할을 한 concept에 넣지 않고, 각각의 genus·관계·공백을 분리해 후속 cluster 입력으로 남긴다.

```text
지속 계약 / instance handle
≠ 현재 runtime state
≠ clock coordination
≠ SelfOn readout
≠ Access-policy attractor
≠ identity tracking hypothesis
≠ continuity work / cost
≠ organismic subject
≠ experiential subject
≠ attribution subject
≠ Ghost / Editor / Actor
```

중심 질문은 다음과 같다.

```text
QUAL13에서 Chapter 03이 아직 추출하지 않은 현상 구조는 무엇인가?
Persona Handle·RuntimeObject·PolicyAttractor는 같은 concept인가?
Cross-Clock Lock은 coordination·readout·firewall 중 무엇인가?
SelfOn과 IdentityTracker는 어떤 실패 조건에서 갈라지는가?
내부 proposal plurality는 identity plurality를 뜻하는가?
Continuity Tax는 작업량·체감 비용·자원 지출·부채 중 무엇인가?
유기체·경험·귀속의 세 주체 자리는 generic 관계인가, 역할 관계인가?
지속 가능하지만 비권위적인 내부 변화는 어느 기존 C-ID도 소유하지 않는가?
기호 재사용을 어느 epoch가 소유하고 다음 Chapter에 무엇을 예약해야 하는가?
```

이번 배치는 Chapter의 답을 현재 정본 인간 ontology로 승인하지 않는다. 역사 문서가 직접 만든 역할, 같은 이름의 이동, 기능 교정, 구조적 공백과 현행 Bridge를 권한별로 분리한다.

### 2.1 파일명·mtime·내용 의존성

`OBJ22`, `SAT22`, `SLEEP22`는 파일명에 `0121`이 남아 있어도 보존 시각상 2026-01-22 지층이다.

`SLEEP22`의 mtime은 `SAT22`보다 74초 빠르지만 내용은 `τ_cont`, tracker, safe-stopping을 전제한다. 따라서 다음만 말한다.

```text
SAT 계열 concept 일부가 SLEEP22 작성 전에 존재했음
```

다음은 말하지 않는다.

```text
SAT22 whole file → SLEEP22 whole file
SAT22-CORRECTION이 SLEEP22보다 반드시 먼저였음
```

## 4. 출처별 주장 권한

| 표지 | 허용 범위 |
|---|---|
| `DIRECT` | 원문이 직접 선언한 역할·관계·금지 |
| `REWRITE` | 같은 이름을 뒤 지층이 다른 역할로 다시 씀 |
| `FUNCTIONAL-CORRECTION` | 뒤 지층이 앞 누수·과잉을 직접 좁힘 |
| `REAL-CONFLICT` | 한 안정 concept로 동시에 유지하기 어려움 |
| `ROLE-DRIFT` | 이름이 identifier·state·readout·policy·process 사이 이동 |
| `TYPE-GAP` | transition·handoff·writer·failure type이 없음 |
| `MODEL-ASSUMPTION` | 증명 결과가 아닌 설계 가정 |
| `OVERGENERALIZATION` | 국소 모델을 인간 일반의 필연으로 확대 |
| `RESIDUE` | 중간 발명 또는 기능이 뒤 통합에서 미봉합 |
| `EARLIER-LINEAGE` | 앞 Chapter에서 복원된 선행 역할 |
| `CURRENT-LENS` | 현행 관점의 비교; 당시 정의가 아님 |
| `BRIDGE-CURRENT` | 구조적 공백에 붙인 현행 가설·임시 명칭 |
| `USER-DIRECT` | 후대 사용자 이론; 0121 직접 근거가 아님 |
| `NON-CLAIM` | 임상·생물학적 사실로 확정하지 않는 edge test |
| `OPEN` | 후속 cluster·Chapter에서 판정할 질문 |

`BRIDGE-CURRENT`, `USER-DIRECT`, `NON-CLAIM`만으로 C-ID, `KEEP`, `MERGE`를 발급하지 않는다.

## 5. identity 역할군 분해

다음 다섯 항목을 한 `Persona` concept로 압축하지 않는다.

```text
PersonaHandle
= 내용이 바뀌어도 instance 계약을 추적하려는 identifier 역할 후보

PersonaRuntimeObject
= π / AddrSig / B_A / θ_H / Seed / trace를 가진 runtime state 후보

SelfOn
= clock coordination이 현재 일체감으로 읽히는 readout 후보

PersonaPolicyAttractor
= 반복적으로 무엇을 열고 닫는지의 policy fixed-point 가설

IdentityTracker
= 이전 단면과 현재 단면을 최소 변경으로 연결하는 가역 추론 과정
```

`ContinuityTax`는 위 다섯 항목과도 다르다. 이는 tracking·stitching에 드는 작업량 또는 비용 후보다.

가능한 관계는 이번 intake에서 확정하지 않는다.

```text
Handle indexes RuntimeObject?
RuntimeObject realizes Attractor?
Tracker follows Handle or current slices?
SelfOn reports ClockCoordination or Tracker stability?
ContinuityTax is part of tracking process or its cost consequence?
```

모든 관계는 `HOLD`다.

## 6. Cross-Clock Lock 분해

`Cross-Clock Lock`은 한 이름 아래 최소 네 역할을 오간다.

```text
ClockCoordination
= t_b / t_e / t_c가 추적 가능한 방식으로 결합

SelfOn
= coordination을 현재 일체감으로 읽는 readout

ClockFirewall
= clock·band 사이 same-tick bypass / reverse flow를 막는 규칙

IdentityHandle
= instance 계보를 추적하는 계약
```

`RTO21-A/B`의 coordination 조건과 `UCXQ21`의 firewall을 synonym MERGE하지 않는다.

`t_c`가 공적 ledger time인지 생물 내부 irreversible attribution time인지도 미확정이다. 공적 commit이 없는 영아·전언어 동물의 경험 주체성을 자동 제외하지 않는다.

## 7. 내부 위원회와 자아의 경계

`OBJ22`가 직접 만든 것은 plural proposal architecture다.

```text
plural proposal objects
→ allocation weight α_t
→ Aggregate
→ one call
```

다음을 금지한다.

```text
proposal object = person / alter
α_t = Warrant / Authority / public reality right
committee consensus = external fact / evidence / identity unity
```

`proposal plurality ? identity plurality`는 `OPEN`이다. 독립 Archive·Episode·handle·worldline이 객체별로 정의되지 않았으므로 identity plurality를 추출하지 않는다.
