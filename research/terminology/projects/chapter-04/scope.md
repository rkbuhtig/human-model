# Chapter 04 Terminology Intake — Scope

## 1. 조사 질문

Chapter 03이 readout과 authority 사이에 세운 벽을 Chapter 04가 왜 다시 문제 삼았고, 그 벽을 허물지 않은 채 어떤 **지연된 인과 경로**를 만들었는지 추출한다.

이 배치는 다음 연속성을 중심으로 읽는다.

```text
Chapter 03
읽히는 값은 현재 원장·선택·적용을 직접 쓰지 못함

→ 과잉 봉인 문제
주관적 값이 아무것도 바꾸지 못하면 인간이 정지함

→ Chapter 04
현재 writer 권한은 계속 금지
다음 tick의 탐색·비교·편성 노동에는 영향 허용
실제 변화는 작업과 회계를 거친 뒤에만 남김
```

핵심 질문은 다음과 같다.

```text
영향을 준다는 것
≠ 사실을 확정할 권한
≠ 선택을 직접 명령할 권한
≠ 정당한 근거 또는 warrant

한 tick 늦는다는 것
≠ 영향이 사라짐
≠ 책임과 귀속이 사라짐

비용을 기록한다는 것
≠ 명제가 참이 됨
≠ 영향이 정당해짐
```

## 2. 연대기 독해 원칙

Chapter 파일명은 주제별 모듈명이 아니라 2026년 1월 15일부터 17일까지 이어진 archive sequence를 나타낸다. 따라서 필요한 명칭만 grep해 독립 항목처럼 읽지 않고, 각 구분이 앞선 실패에 대한 어떤 교정으로 생겼는지 시간 순서대로 본다.

```text
TNE15
→ DIA16
→ ALN16 / RHY16
→ META16
→ POT17 / JRN17
→ TOP17
→ R04
→ R05

병렬 기술 지층:
U17

최종 aggregate:
F17 = 기존 canon + U17 + R05
```

다음 관계를 자동 상속으로 읽지 않는다.

- TNE15 → DIA16은 강한 문언·문제 연속성이지만 명시 상속은 아니다.
- UL15와 RATION은 구조적으로 닮았지만 직접 계승 관계가 아니다.
- Story add-only branch, Interaction Economics branch, RATION branch, U17 technical branch는 같은 날짜에 존재해도 하나의 단일 직선 계보가 아니다.
- `F17`에 함께 수록됐다는 사실은 모든 하위 문장이 동일 실행 권한을 가졌다는 뜻이 아니다.

## 7. `X/R/U/A` 처리 규칙

`X/R/U/A`는 현재 terminology의 전역 분류표로 가져오지 않는다.

```text
X/R/U/A
= RATION v0.5가 여러 역할의 누수를 찾으려고 사용한
  역사적 residence audit

X/R/U/A
≠ 현재 ontology
≠ concept 파일의 필수 필드
≠ 현행 authority type system
≠ 네 개의 자동 C-ID
```

그 이유는 Chapter 자체가 다음 미폐쇄를 확인하기 때문이다.

- `X`가 persistence와 writer authority를 섞는다.
- `CovState`는 네 칸 안에서 거주지가 닫히지 않는다.
- `MeaningFlux`가 `R`과 `A`에 동시에 놓인다.
- `A`는 같은 aggregate 안에서 Attention과 Accounting으로 충돌한다.
- X/R/U/A 네 칸은 서로 다른 추상 수준을 섞는다.
- `U_{t+1}`와 현재 실행·회계 사이의 clock convention이 닫히지 않는다.

따라서 extraction map에는 다음 두 가지만 남긴다.

1. 당시의 역사적 residence audit 시도
2. 그 audit가 발견한 유용한 질문과 자체 실패

네 글자 분류 자체를 보존해야 할 현재 concept로 승격하지 않는다.

## 9. 조사 원칙

1. Chapter 04의 후대 명칭을 Chapter 03 후보의 정답으로 소급하지 않는다.
2. 영향, 권한, 근거, warrant, 비용, truth를 한 축으로 묶지 않는다.
3. `next-tick`을 합법적 승격의 충분조건으로 취급하지 않는다.
4. readout이 Select writer가 아니어도 유한 탐색의 후보 발견에 인과적으로 기여할 수 있음을 보존한다.
5. 실제 작업을 요구하는 것과 최대 작업량을 요구하는 것을 구분한다.
6. social influence와 정당한 obligation·authority를 구분한다.
7. `Priority`의 readout 역할과 `GateBias`의 운영 역할을 분리한다.
8. `Coverage`를 존재·자기경계·기억 소유권과 자동 통합하지 않는다.
9. potential을 constraint tension, persistent lock stock, unused output slack으로 분리한다.
10. `X/R/U/A`는 역사적 audit로만 기록하며 현재 분류 체계로 채택하지 않는다.
11. 후보 설명의 단일 권위는 `extraction-map.md`다. `basic-term-list.md`는 명칭 색인만 제공한다.

## 11. 완료 조건

- Chapter 03의 authority wall이 왜 과잉 봉인 문제를 만들었는지 추적 가능하다.
- readout이 current writer 권한 없이 next-tick 탐색·비교 노동에 영향을 주는 경로가 분리된다.
- causal influence와 selection authority·warrant가 구분된다.
- same-tick 금지의 역할이 영향 제거가 아니라 자기확증 차단으로 보존된다.
- actual-work 결박과 no-discount가 최대 Spend 의무와 구분된다.
- Priority와 GateBias, Coverage와 existence/self-boundary가 섞이지 않는다.
- potential의 세 역할이 다시 한 후보로 접히지 않는다.
- `X/R/U/A`가 현재 ontology로 오인되지 않고, 역사적 audit와 실패만 추적된다.
- UL과 RATION의 구조적 유비가 직접 상속으로 오인되지 않는다.
- policy influence provenance, outcome record, evidence, warrant의 공백이 명시된다.
