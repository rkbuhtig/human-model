# 다른 역할이라고 다른 개념인 것은 아니다

> 날짜: 2026-08-07  
> 지위: 비권위 연구 일기

Chapter 09부터 Chapter 11까지 계속 같은 교정을 해 왔다.

```text
같은 사람을 설명한다
≠ 같은 concept

같은 수면 구간에 나타난다
≠ 같은 concept

같은 변화를 설명한다
≠ 같은 concept
```

이 교정은 필요했다. 실제로 이 저장소는 이름이나 장면의 결합을 concept 동일성으로 너무 쉽게 읽은 적이 있었다. PR #44의 `MERGE`가 대표적이었다. 이후 cardinality 교정은 그 압축을 다시 풀었다.

그런데 Chapter 11 intake를 끝내고 adjudication으로 넘어가자 반대쪽 위험이 보였다.

> 계속 잘 분리해 온 습관이 이제는 분리 자체를 판정처럼 느끼게 만들 수 있다.

`Persistent Non-Authority`가 그 시험대였다.

처음에는 이 이름 아래 모인 것들을 보면 쉽게 이렇게 정리할 수 있었다.

```text
C0006
≠ RoutingField
≠ PlasticState
≠ UpdateOperator
≠ StateDelta
≠ PlasticResidue
≠ UpdateSignature
≠ TraceRecord
≠ ShapingClaimSignature
≠ 𝔄
```

이 비동일성 목록은 안전해 보인다. 실제로 state와 record, relation과 entity, authority register를 합치면 안 된다.

하지만 이 목록을 그대로 concept cardinality로 읽으면 또 다른 오류가 생긴다.

```text
서로 다른 역할 이름이 있다
→ 서로 다른 concept가 있다
```

이건 앞에서 고친 오류의 반대 방향일 뿐이다.

그래서 이번 cluster에서는 처음부터 같은 가설과 다른 가설을 나란히 뒀다.[^1]

```text
H_same
차이는 이름·epoch·구현·시점 역할일 뿐이고
실제로는 같은 concept다.

H_distinct
서로 다른 genus·differentia·identity criterion을 가진다.
```

[^1]: PR #53, commit `f4e7f96` — cluster adjudication에 동일성/차이 대칭 규율을 추가함.

## `PlasticResidue`가 처음 걸렸다

가장 흥미로운 후보는 `PlasticResidue`였다.

Chapter 11 intake에서는 일부러 이렇게 갈랐다.

```text
PlasticState
= 지속 가능한 내부 state 후보

PlasticStateDelta
= 실제 적용된 변화 후보

PlasticResidue
= update 뒤 남은 causal state 후보
```

추출 단계에서는 이게 맞다. 셋을 같은 단어로 덮으면 transition과 state와 persistence가 다시 섞인다.

그런데 adjudication 단계에서 질문을 바꾸면 상황이 달라진다.

```text
PlasticResidue가 정말 별도 object인가?
```

현재 자료가 말하는 residue는 대체로:

```text
M_t --update--> M_{t+1}

M_{t+1}에서
그 update 때문에 달라졌고
이후 causality를 바꾸는 부분/측면
```

이다.

그렇다면 `PlasticResidue`는 독립 substance라기보다 **PlasticState를 특정 update에 상대적으로 바라본 result-role**일 수 있다.

이때:

```text
PlasticState ≠ PlasticResidue
```

라고 역할을 분리해서 말하는 것은 가능하지만:

```text
PlasticState concept
≠
PlasticResidue concept
```

라고 두 C-ID를 발급하는 것은 아직 정당화되지 않는다.

이번 cluster에서 처음으로 분명하게:

```text
PlasticResidue
NOT YET DISTINCT-CONCEPT-FROM PlasticState
```

라고 적었다.[^2]

[^2]: PR #53, commit `4f4b360` — `PlasticResidue`를 독립 concept가 아니라 update-relative result-role 후보로 판정함.

이 문장이 중요하다.

지금까지는 후보를 합치지 않는 것이 주로 안전장치였다. 이제는 **후보를 분리해 놓았다고 해서 concept까지 분리하지 않는 것**도 안전장치가 됐다.

## `residue ≠ record`는 그대로 살아남았다

반대로 `PlasticResidue`와 `PlasticTraceRecord`는 같은 방식으로 접을 수 없었다.

```text
PlasticResidue
= 실제 이후 causality를 바꾸는 alteration

PlasticTraceRecord
= 그 alteration에 관한 representation
```

둘은 독립적으로 실패할 수 있다.

```text
residue는 있는데 record가 없음

record는 있는데 residue를 잘못 기술함
```

이건 단순 역할 시점 차이가 아니다. 존재 조건과 정확성 조건이 다르다.

그래서 여기서는 `DISTINCT-ROLE`이 강하게 살아남았다.[^2]

중요한 것은 결과가 `같다`냐 `다르다`냐가 아니다.

같은 질문을 양쪽에 적용했을 때:

```text
PlasticState / PlasticResidue
→ 별도 concept 판정 보류

PlasticResidue / PlasticTraceRecord
→ state / representation 역할 차이 확정
```

처럼 결과가 갈렸다는 점이다.

## `ShapingSig`는 실제로 같은 것을 같다고 봤다

분리 편향을 시험하려면 실제 sameness도 찾아야 했다.

Chapter 11 intake에서 나는 `ShapingSig`를 `ShapingClaimSignature`라고 다시 불렀다.

```text
ShapingSig
= MetricEpoch + Window + Region + LinkedAudit
```

이 이름을 바꾼 이유는 새 object를 만들기 위해서가 아니었다.

`PlasticUpdateSignature`와 구분해서:

```text
internal transition description
≠ authority-facing shaping claim metadata
```

를 드러내기 위해서였다.

따라서:

```text
ShapingSig@NEWQUAL22
SAME-CONCEPT-ROLE
ShapingClaimSignature@CHAPTER-SYNTHESIS
```

라고 판정했다.[^2]

그런데 `MERGE`는 하지 않았다.

왜냐하면 두 번째 이름은 독립적으로 역사 자료에서 사용된 synonym이 아니라 현재 분석을 위해 붙인 disambiguating label이기 때문이다.

이 구분 덕분에:

```text
SAME-CONCEPT 판정
≠ synonym MERGE action
```

도 처음으로 선명해졌다.

`MERGE 0`이라는 숫자만 보면 이번에도 아무것도 합치지 않은 것처럼 보인다. 하지만 실제 판단 과정에서는 같은 역할을 같은 것으로 판정했다.

## `Persistent Non-Authority`에는 공통 genus가 없었다

처음 이름 자체가 강한 유혹이었다.

```text
persistent
+
non-authoritative
```

두 특성을 만족하는 무언가가 있고, 그 무언가의 이름을 찾으면 될 것처럼 보인다.

하지만 primary input을 다시 놓으면 이 두 특성조차 모든 항목에 같은 방식으로 적용되지 않는다.

```text
C0006
= relation이고 persistence가 필수 아님

RoutingField
= current context condition일 수 있음

UpdateOperator
= rule

StateDelta
= transition difference

TraceRecord
= representation

ShapingClaimSignature
= authority application과 연결되는 claim metadata

𝔄
= 아예 authority-side register
```

그래서 `Persistent Non-Authority`는 genus가 아니라 질문 이름이었다.

이번 판정은:

```text
Persistent Non-Authority
→ CHARACTERISTIC-OVERLAP / QUESTION LABEL
```

이다.[^2]

여기서 더 중요한 생각이 하나 생겼다.

```text
persistence
non-authority
causal efficacy
recordability
auditability
```

는 한 계층의 sibling type들이 아니라 서로 직교할 수 있는 facet일 가능성이 크다.

예를 들어 어떤 state는 persistent하지만 record되지 않을 수 있고, 어떤 record는 persistent하지만 causal state가 아닐 수 있고, 어떤 influence relation은 causal하지만 persistent entity가 아닐 수 있다.

즉 분류 축 자체를 concept hierarchy로 착각하면 안 된다.

## cardinality는 파일 수가 아니었다

이번 cluster에 입력 이름은 열 개였다.

그렇다고 cardinality가 10인 것은 아니다.

결과는 더 이상한 모양이다.

```text
1 existing KEEP relation
+ unresolved current condition
+ broad persistent state candidate
+ transition rule role
+ transition delta role
+ state의 result-relative role
+ metadata role
+ record role
+ historical role과 같은 analytical relabel
+ authority-side boundary register
```

이걸 몇 개 concept라고 지금 숫자로 말하는 것 자체가 틀릴 수 있다.

`PlasticUpdateOperator`나 `PlasticStateDelta`는 독립 인간 concept가 아니라 모델의 transition vocabulary일 수 있다. `PlasticResidue`는 state의 관계적 역할일 수 있다. `ShapingClaimSignature`는 별도 concept라기보다 특정 audit contract의 metadata role일 수 있다.

그래서 새 C-ID가 0개라는 결과가 처음으로 자연스럽게 느껴졌다.

예전의 0은 주로:

```text
아직 근거가 부족하니 HOLD
```

였다.

이번 0은 일부 항목에 대해:

```text
애초에 새 concept를 발급하는 질문이 잘못됐다
```

라는 판정을 포함한다.

## intake와 adjudication은 태도가 달라야 했다

intake에서는 잃어버리는 것보다 과하게 남기는 게 낫다.

```text
같아 보임
→ 일단 분리 보존
```

이 방식이 맞다.

하지만 adjudication에서 같은 태도를 계속 쓰면 모든 role difference가 C-ID가 된다.

그래서 지금은 이렇게 구분하는 편이 맞다.

```text
intake
= collapse를 막는다

adjudication
= collapse와 fragmentation을 둘 다 시험한다
```

`HOLD`도 의미가 달라진다.

intake의 HOLD는:

```text
아직 건드리지 않음
```

에 가까울 수 있다.

adjudication의 HOLD는 가능하면:

```text
여기까지는 판정했고
이 exact condition이 없어서 여기부터는 못 닫음
```

이어야 한다.

이번 `RoutingField`가 그렇다.

우리는 이미:

```text
RoutingField ≠ C0006 relation
```

은 판정했다.

하지만:

```text
RoutingField
= PlasticState의 projection인가?
= context-derived function인가?
= 독립 current state인가?
```

는 닫지 못했다.

그러면 HOLD의 재개 조건은 더 많은 추출이 아니라:

```text
같은 substrate + 다른 context
다른 substrate + 같은 context
```

같은 독립 대비다.

## queue도 줄이는 방식이 달라졌다

`Persistent Non-Authority`를 끝냈다고 그 아래 이름들을 여섯 개 새 cluster로 풀면 아무것도 줄지 않는다.

그래서 남은 질문을 다시 기능별 family로 보냈다.[^2]

```text
Routing Policy

Plastic State / Transition / Provenance

Shaping Certification / Typed Accounting
```

`Plastic State / Transition / Provenance`도 하나의 concept라는 뜻은 아니다. 서로 붙어 있는 판정 질문을 한 번에 비교하기 위한 adjudication family다.

이 차이를 잊으면 queue 압축이 ontology 압축으로 변한다.

## 지금 남은 가장 큰 경계

첫 adjudication을 끝내고 나니 `Persistent Non-Authority`보다 다음 질문이 오히려 더 어렵게 보인다.

```text
PhenomenalEpisode
Morph
Report
C0005 current experiential surface
```

여기서는 state / record처럼 문법적으로 뻔한 분리보다:

```text
겪어진 것
현재 주어진 표면
그 형상 모델
그것에 대한 보고
```

사이의 관계를 판정해야 한다.

그리고 여기서도 같은 규율이 필요하다.

```text
같은 경험 장면에 있다는 이유로 합치지 않는다.

다른 역할 이름이 있다는 이유로 쪼개지도 않는다.
```

Persistent Non-Authority cluster가 실제 adjudication phase의 첫 시험이 된 이유는 이 두 문장을 동시에 쓸 수 있게 했기 때문이다.
