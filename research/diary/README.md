# Research Diary

`research/diary/`는 연구 과정에서 생긴 직감, 의심, 구조적 발견을 자유롭게 기록하는 공간이다. 일기는 concept 정의, 전문용어 판정, glossary 또는 현재 이론의 정본 근거가 아니다.

## 경로

```text
research/diary/YYYY-MM-DD/부제.md
```

한 날짜에 여러 생각이 있으면 파일을 나누고, 제목은 그 기록의 내용을 드러내는 자연어로 쓴다.

## 작업 출처 인용

일기는 먼저 하고 싶은 말을 자연스럽게 쓴다. 특정 PR이나 커밋 작업에서 얻은 관찰·의심·통찰은 그 생각이 적힌 문장이나 문단 뒤에 Markdown 각주로 출처를 남긴다.

```markdown
입력 범위가 개념의 집이 되면 같은 개념이 배치마다 복제된다.[^1]

[^1]: PR #34, commit `699162c` — terminology research ownership and method.
```

출처는 다음 원칙을 따른다.

- 문서 앞머리에 PR·커밋 목록을 일괄 배치하지 않는다.
- 일기 본문을 출처 형식에 맞춰 다시 구조화하지 않는다.
- 한 PR에 포함된 모든 커밋을 기계적으로 나열하지 않는다.
- 해당 생각을 실제로 만들거나 구체화한 커밋만 적는다.
- 한 생각이 여러 커밋을 거쳐 생겼다면 필요한 커밋들을 같은 각주에 함께 적는다.
- 동일한 출처를 공유하는 문장이나 문단은 같은 각주를 다시 참조할 수 있다.
- 각주에는 PR 번호, 짧은 commit SHA, 해당 커밋에서 수행한 작업을 알아볼 수 있는 짧은 설명을 남긴다.
- 출처를 확인할 수 없는 커밋 번호를 추측해서 만들지 않는다.

출처 각주는 그 생각이 옳다는 증명이 아니다. 그 생각이 어떤 저장소 작업에서 생겼는지를 다시 추적하기 위한 provenance다.
